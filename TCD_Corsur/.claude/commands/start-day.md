# /start-day — 작업 시작 준비

GitHub 최신 코드를 가져오고, 어제까지의 작업 현황을 요약해 오늘 작업을 바로 시작할 수 있게 준비한다.

---

## 실행 순서

### 1. 현재 상태 파악
아래 명령을 병렬로 실행한다.
```
git status
git branch -vv
git log --oneline -8
```

### 2. 원격 변경사항 가져오기
```
git fetch --all --prune
```
fetch 후 원격과의 차이를 확인한다.
```
git log --oneline HEAD..origin/<현재 브랜치>
```
출력이 있으면 "원격에 새 커밋이 있습니다" 메시지와 함께 커밋 목록을 보여준다.

### 3. Pull (원격이 앞서 있을 때만)
원격에 새 커밋이 있으면 아래를 실행한다.
```
git pull --rebase origin <현재 브랜치>
```
- rebase 충돌 발생 시 충돌 파일 목록을 알리고 중단한다.
- 현재 브랜치가 원격보다 앞서 있거나 동일하면 pull 없이 진행한다.

### 4. 빌드 상태 확인
```
dotnet build TCD_Corsur.sln --no-restore -v q 2>&1 | tail -5
```
빌드 에러가 있으면 에러 메시지를 그대로 출력하고 "빌드 실패 — 코드 수정 후 다시 시도하세요"를 안내한다.
에러 없으면 "빌드 정상" 표시.

### 5. 마지막 작업 로그 확인
`D:\project\TCD_Cursor\docs\WORKLOG.md` 파일의 상단 30줄을 읽어 가장 최근 작업 항목을 보여준다.
파일이 없으면 이 단계는 건너뛴다.

### 6. main 브랜치와의 차이 요약
```
git log --oneline main..HEAD
git diff --stat main...HEAD
```
현재 브랜치가 main보다 몇 커밋 앞서 있는지, 어떤 파일이 변경됐는지 요약한다.
현재 브랜치가 `main`이면 이 단계는 건너뛴다.

### 7. 최종 리포트 출력

아래 형식으로 오늘 작업 시작 요약을 출력한다.

```
🚀 작업 시작 준비 완료

브랜치:      <branch> (로컬 <N>커밋 앞서 있음 / 최신 상태)
빌드:        ✅ 정상 / ❌ 실패
원격 동기화: ✅ 최신 / ⬇️ N커밋 pull 완료

--- 마지막 작업 ---
<WORKLOG.md의 가장 최근 항목 요약>

--- main 대비 변경 파일 ---
<git diff --stat 결과 요약>

💡 다음 작업 제안: <WORKLOG.md 또는 ROADMAP.md 기반으로 이어서 할 작업 한 줄 제안>
```

---

## 주의
- `git pull --force` 또는 `git reset --hard`는 절대 사용하지 않는다.
- 충돌 발생 시 자동 해결하지 않고 사용자에게 파일 목록을 알리고 중단한다.
- 빌드 실패 시에도 중단하지 않고 리포트에 포함해 알린다.
